# ETL Pipeline для PostgreSQL 14

## Описание

ETL pipeline для обработки nightly SQL-дампов PostgreSQL. Работает на Ubuntu 22.04 
без внешних зависимостей (использует только стандартную библиотеку Python).

## Структура проекта

```
/workspace/
├── config/
│   └── etl_config.ini      # Конфигурационный файл
├── scripts/
│   └── etl_pipeline.py     # Основной скрипт ETL
├── dumps/                  # Директория для SQL-дампов
│   ├── test_dump_v1.sql    # Тестовый начальный дамп
│   └── test_dump_v2.sql    # Тестовый ночной дамп
├── logs/                   # Директория для логов
└── run_tests.sh            # Скрипт тестирования
```

## Требования

- PostgreSQL 14
- Python 3.x (стандартная библиотека)
- Ubuntu 22.04

## Установка

1. Убедитесь что PostgreSQL запущен:
```bash
sudo systemctl start postgresql
sudo systemctl enable postgresql
```

2. Проверьте доступность PostgreSQL:
```bash
pg_isready -h localhost -p 5432 -U postgres
```

3. При необходимости настройте аутентификацию в `/etc/postgresql/14/main/pg_hba.conf`:
```
local   all             postgres                                peer
host    all             all             127.0.0.1/32            trust
```

## Использование

### Первый запуск (инициализация)

Создает основную базу данных и загружает начальный дамп:

```bash
python3 /workspace/scripts/etl_pipeline.py --init /path/to/initial_dump.sql
```

### Обработка ночных дампов

Разворачивает дамп во временной базе, находит изменения и синхронизирует с основной базой:

```bash
python3 /workspace/scripts/etl_pipeline.py /path/to/nightly_dump.sql
```

### Обработка с очисткой временной базы

```bash
python3 /workspace/scripts/etl_pipeline.py --cleanup /path/to/nightly_dump.sql
```

## Автоматизация (cron)

Для запуска каждый день в 2:00 ночи добавьте в crontab:

```bash
crontab -e
```

Добавьте строку:
```
0 2 * * * cd /workspace && python3 /workspace/scripts/etl_pipeline.py --cleanup /path/to/nightly/dump_$(date +\%Y\%m\%d).sql >> /workspace/logs/cron.log 2>&1
```

## Конфигурация

Отредактируйте `/workspace/config/etl_config.ini` для настройки:

- Имена баз данных (основная и временная)
- Параметры подключения к PostgreSQL
- Пути к директориям
- Настройки логирования
- Размер пакетов для обработки

## Как это работает

1. **Инициализация**: Создается основная база данных (`main_db`) и загружается начальный дамп

2. **Ночная обработка**:
   - Новый дамп разворачивается во временной базе (`temp_db`)
   - Для каждой таблицы с первичным ключом:
     - Находятся новые строки (есть во временной, нет в основной)
     - Находятся измененные строки (есть в обеих, но данные отличаются)
     - Выполняется UPSERT (INSERT ... ON CONFLICT DO UPDATE)
   - Временная база удаляется (если указан флаг `--cleanup`)

3. **Логирование**: Все операции логируются в `/workspace/logs/`

## Тестирование

Запустите тестовый скрипт:

```bash
./run_tests.sh
```

Скрипт:
1. Очищает старые тестовые базы
2. Инициализирует основную базу с `test_dump_v1.sql`
3. Обрабатывает `test_dump_v2.sql` с изменениями
4. Проверяет что изменения применены корректно
5. Тестирует очистку временной базы

## Особенности

- **Без внешних зависимостей**: Использует только стандартную библиотеку Python
- **Работа через psql**: Все операции с БД выполняются через утилиту командной строки psql
- **Поддержка нескольких таблиц**: Автоматически обнаруживает все таблицы в дампе
- **Определение первичных ключей**: Автоматически находит PK для каждой таблицы
- **UPSERT**: Использует INSERT ... ON CONFLICT для эффективной синхронизации
- **Логирование**: Подробное логирование всех операций

## Ограничения

- Таблицы без первичного ключа пропускаются
- Удаленные строки не синхронизируются (только добавление и обновление)
- Все таблицы должны быть в схеме `public`

## Логи

Логи сохраняются в `/workspace/logs/etl_YYYYMMDD_HHMMSS.log`

Для просмотра последних логов:
```bash
ls -lt /workspace/logs/ | head
tail -f /workspace/logs/etl_*.log
```
